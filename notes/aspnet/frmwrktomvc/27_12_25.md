# Migrating from ASP.NET WebForms to ASP.NET Core 10 MVC

Theme: From Event-Driven Programming to HTTP Request–Response Programming

TRANSFLOWER LEARNING · MENTOR-LED CLASSROOM SESSION

> Don't migrate your WebForms coding habits into ASP.NET Core. Migrate your understanding of web application development.

## 1. Start with a classroom conversation

Mentor: In WebForms, how did you execute business logic when a user clicked a button?

Student: We created a Button control and wrote code inside its Click event.

Mentor: Correct. What happened when the button was clicked?

Student: The page generated a PostBack. The server executed the event handler and returned the updated page.

Mentor: Excellent! Now think about this: Does the browser really understand Button_Click, Page_Load or ViewState?

Student: No. The browser understands HTTP requests and responses.

Mentor: Exactly! ASP.NET WebForms provided an abstraction over HTTP. ASP.NET Core MVC makes the HTTP request–response model more visible.

The architectural difference:

| WebForms        | ASP.NET Core MVC          |
| --------------- | ------------------------- |
| Page lifecycle  | HTTP request lifecycle    |
| Page_Load       | Controller action         |
| Button_Click    | POST action               |
| ViewState       | Explicit state management |
| Master Page     | Razor Layout              |
| GridView        | HTML table + model        |
| Code Behind     | Controller + Services     |
| Server Controls | HTML + Tag Helpers        |

One important distinction: a controller action is an HTTP endpoint when routing and HTTP method constraints map requests to it. Not every public method is automatically an endpoint.

## 5. Understand Program.cs

This is one of the most important files in ASP.NET Core.

```
var builder = WebApplication.CreateBuilder(args);

// Register MVC services
builder.Services.AddControllersWithViews();
var app = builder.Build();

// Configure HTTP pipeline
if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/Home/Error");
    app.UseHsts();
}

app.UseHttpsRedirection();
app.UseStaticFiles();
app.UseRouting();
app.UseAuthorization();

// Configure default route
app.MapControllerRoute(name: "default",pattern: "{controller=Home}/{action=Index}/{id?}");
app.Run();
```

Explain the execution sequence:

1. Create application builder.
2. Register dependencies and MVC services.
3. Build the application.
4. Configure middleware.
5. Configure routing.
6. Start the web server.

Important mentor concept: Middleware forms the pipeline through which HTTP requests and responses travel. Order matters.

## 6. Build your first Controller

`Controllers/ProductController.cs`

```
using Microsoft.AspNetCore.Mvc;

public class ProductController : Controller
{
    public IActionResult Index()
    {
        return Content("Welcome to Product Management");
    }

    public IActionResult Details(int id)
    {
        return Content($"Product ID: {id}");
    }
}
```

## 7. Introduce Models and Razor Views

Create Model: Models/Product.cs

```
{

    public string Name { get; set; } = "";

```

```
using Microsoft.AspNetCore.Mvc;
```

## 8. Give students a WebForms-to-MVC migration exercise

Ask them to compare these two approaches.

Old WebForms approach

```
protected void btnSave_Click(object sender, EventArgs e)
{
    string name = txtName.Text;
    lblMessage.Text = "Welcome " + name;
}
```

ASP.NET Core MVC approach

Controller:

```
[HttpGet]
public IActionResult Create()
{
    return View();
}

[HttpPost]
public IActionResult Create(string name)
{
    ViewBag.Message = "Welcome " + name;
    return View();
}
```

View:

```
<form asp-controller="Product" asp-action="Create" method="post">
    <label>Name</label>
    <input type="text" name="name" />
    <button type="submit">Save</button>
</form>

<h2>@ViewBag.Message</h2>
```

Here the browser sends an HTTP POST request. ASP.NET Core model binding extracts the submitted value and passes it to the action.

For production forms, introduce view models, validation attributes, `ModelState.IsValid`, anti-forgery protection and Post/Redirect/Get.

## 11. What should students learn next?

I recommend teaching the concepts in this sequence:

1. MVC Fundamentals

   Controllers, Actions, Routing, Razor Views
2. HTTP Fundamentals

   GET, POST, PUT, DELETE, Status Codes, Middleware
3. Model Binding and Validation

   ViewModels, Data Annotations, ModelState
4. Dependency Injection

   Interfaces, Services, Singleton, Scoped, Transient

   Authentication, Authorization, Identity, JWT
7. Testing

   xUnit, Integration Testing, WebApplicationFactory, Playwright
8. Deployment

   Docker, CI/CD, Cloud Hosting, Observability

## Mentor's closing message

> WebForms taught us how to build web pages using server-side events.
>
> ASP.NET Core teaches us how to build web applications using HTTP, middleware, routing, dependency injection and well-separated components.
>
> Don't just learn a new framework. Upgrade your software engineering mindset.

My recommendation: Use the Product Management application as the continuous classroom project. Start with in-memory data, introduce services and dependency injection, move to EF Core and MySQL, then expose the same business functionality through ASP.NET Core Web API.

This way, students learn MVC, REST APIs, database programming, testing and architecture through one evolving project.
